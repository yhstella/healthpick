## 3. P1: 감수 표시를 실제 검토 기록과 연결

근거: [ArticleLayout.astro:32](/E:/healthpick/src/layouts/ArticleLayout.astro:32), [같은 파일:162](/E:/healthpick/src/layouts/ArticleLayout.astro:162), [표시 부분:295](/E:/healthpick/src/layouts/ArticleLayout.astro:295), [콘텐츠 스키마](/E:/healthpick/src/content/config.ts:20).

현재 `reviewedDate = data.updatedDate ?? data.pubDate`다. `medical:true`이면 전역 감수자 정보와 이 날짜로 '의료 감수', '최종 검토', `reviewedBy`, `lastReviewed`를 출력한다. 게시일·문구 수정일·의료 검토일은 서로 다른 사실인데 하나로 취급한다.

실제 사례: [혈압약 시작 후 6주 점검 글](https://healthpick.kr/health/혈압-145-90-약-시작-6주-점검/)은 Git에 7월 30일 본문 보강 이력이 있는데 `updatedDate`가 없다. 라이브에는 **최종 검토 2026년 5월 23일**이 표시되고 JSON-LD의 `dateModified`와 `lastReviewed`도 5월 23일이다. 이 날짜로 현 본문이 언제 검토됐는지 알 수 없다.

**수정 요청**

1. 기존 스키마 안에 글별 감수자 ID, 실제 감수일, 검토 상태를 구분할 수 있는 최소 필드를 추가한다. 기존 편집부/감수자 프로필은 재사용한다.
2. 감수 기록을 확인한 글에만 해당 감수 표시를 출력한다. `medical:true`는 의료 주제라는 분류이지 승인 증빙이 아니다.
3. 실제로 검토한 본문 버전을 식별한다. 새 시스템이 거창할 필요는 없고, 감수 기록과 커밋 또는 본문 버전을 연결하는 방식이면 된다. 코드만 변경한 커밋 때문에 모든 감수를 무효화하는 구조는 피한다.
4. 단순 오탈자 교정일과 의료 판단이 바뀐 수정일을 구분한다. 핵심 내용 변경 뒤에는 과거 감수를 최신 본문 감수처럼 표시하지 않는다.
5. 과거 감수 여부와 날짜를 운영자에게 확인한다. 모르는 날짜를 게시일·오늘 날짜·최근 커밋일로 일괄 채우지 않는다. 기록 미확인과 실제 미감수도 구분한다.
6. 소개·편집절차의 '모든 의료 글은 게시 전에 검토'라는 문구도 실제 운영과 일치시킨다. 미확인 기존 글은 상태·위험도를 확인해 개별 처리하고, 84편 전체를 즉시 내리는 식으로 대응하지 않는다.

**완료 기준**: 기록 없는 테스트 글에는 검토 완료 문구와 `reviewedBy`/`lastReviewed`가 나오지 않는다. 기록 있는 글의 화면·JSON-LD가 동일한 실제 감수 정보를 쓴다. 발행일 수정만으로 감수일이 바뀌지 않는다. 의료 내용이 바뀐 뒤 재검토가 필요한 경우를 테스트한다.

## 5. P1: 출처를 '기관 이름'에서 '확인 가능한 근거'로 전환

현재 55편에는 기관 홈페이지 첫 화면을 가리키는 frontmatter 출처가 하나 이상 있다. 예를 들어 혈압약 글의 '국가건강정보포털 고혈압 정보'는 `https://health.kdca.go.kr/`, '보건복지부 만성질환 관리'는 `https://www.mohw.go.kr/`다. 독자는 어느 문서가 해당 기준을 말하는지 바로 확인할 수 없다.

**수정 요청**

1. 숫자 기준, 약 시작·증량·중단, 재검사 간격, 검사 급여·비용, 위험 신호를 먼저 뽑아 주장별 근거 대조표를 만든다. 모든 문장에 링크를 붙이거나 출처 개수를 강제하는 작업은 아니다.
2. 근거표에 실제 문서 제목·발행 주체·연도/버전·직접 URL·관련 절/쪽수·적용 대상을 기록한다. 문서가 주장하지 않는 인과관계나 조건을 덧붙이지 않는다.
3. 200 응답을 받는다고 검증 완료가 아니다. 로그인 화면·기관 첫 화면으로의 리다이렉트·제목 다른 문서도 확인한다. 반대로 403/타임아웃만으로 가짜 출처라고 단정하지 않는다.
4. 국내 약 복용·급여·비용에는 국내 허가사항·공식 고시를 우선 확인한다. 외국 지침을 인용하면 국가·대상·차이를 밝힌다.
5. 검증된 원문을 찾지 못한 구체적 기준은 추정으로 채우지 말고, 해당 단정 표현을 보류하거나 삭제한 뒤 감수자에게 질의한다.
6. 본문 참고 목록과 frontmatter `sources`의 중복 관리 방식을 정리한다. 하나를 기준으로 렌더링하되 문단별 근거 위치를 잃지 않게 한다.
7. [출처 하단 문구](/E:/healthpick/src/layouts/ArticleLayout.astro:380)의 '위 출처는 … 1차 근거'는 실제 자료 유형에 맞춘다. 보도기사·환자용 안내·원 연구·진료지침은 구분해야 한다.

먼저 볼 3편: **근지구력 운동 초보 가이드 / 로우 푸드 / 외상 후 스트레스 장애**. 두 위치 모두에 참고 URL이 발견되지 않았다. 소화불량·항히스타민제는 본문 출처가 있으므로 '무출처'가 아니라 메타데이터와 원문 적합성을 정비한다.

**완료 기준**: 첫 수정 묶음의 핵심 판단·수치마다 연결 가능한 근거와 적용 범위를 제시한다. 기관 첫 화면 링크만으로 해당 판단의 근거 검증을 통과시키지 않는다. 출처 이름과 실제 발행 주체가 일치한다.

### 6.2 비활성 자동 발행의 재개 조건

## 8. P2: 메인에서 실제로 하지 않는 일을 약속하지 말 것

근거: [index.astro:35](/E:/healthpick/src/pages/index.astro:35), [43행](/E:/healthpick/src/pages/index.astro:43), [56행](/E:/healthpick/src/pages/index.astro:56), [111행](/E:/healthpick/src/pages/index.astro:111).

- **'최신 글'**: 추천에 뽑힌 글을 제외한다. 독자가 예상하는 전체 최신순과 다르다. 실제 최신 목록으로 만들거나 겹침을 피한 편집 목록에 맞는 이름을 붙인다.
- **'매주 새 글 + 본문 보강 / 이번 주는 … 보강하고 있습니다'**: 현재 작업 기록을 반영하는 데이터가 아니라 하드코딩이다. 지킬 수 있는 운영 설명으로 바꾸거나 실제 편집 기록과 연결한다.
- **'건강 인기 글'**: [ArticleLayout.astro:417](/E:/healthpick/src/layouts/ArticleLayout.astro:417)의 추천은 조회수 기반 인기도가 아니다. '함께 읽을 글'처럼 선정 방식에 맞게 바꾼다.

3. 중요 URL 표본의 URL 검사: 마지막 크롤링, 색인 가능 여부, 사용자 canonical과 Google 선택 canonical, 제외 사유. 이번 sitemap 일치 검사는 이 정보를 대신하지 않는다.
4. GSC 수동 조치·보안 문제 상태. 확인 없이 penalty라고 부르지 않는다.
5. AdSense의 가장 최근 사이트 상태·반려 원문·신청/통지 날짜. 계정 승인, 특정 사이트 승인, 실제 광고 게재를 구분한다.
6. 측정 가능한 경우 GA4 유입 채널·랜딩 페이지·기기와 실제 페이지 속도 자료. 동의 설정·추적 누락 등 계측 조건도 확인한다.

자료에 따른 분기: 크롤링/색인 문제면 HTTP·robots·canonical·내부 발견 경로를 먼저 확인한다. 색인됐지만 노출이 적으면 실제 검색어의 수요·경쟁·답의 차별성을 본다. 노출은 있는데 클릭이 적으면 해당 검색어·기기·순위 맥락에서 제목/요약을 검토한다. 클릭 뒤 문제가 의심되면 실제 사용성·계측을 확인한다. **이 분기를 생략하고 매번 '글을 늘리자'로 돌아가지 않는다.**

AdSense는 검색 순위와 별도 판정이다. Google 게시자 정책은 가치가 낮거나 콘텐츠가 없는 화면 등에서의 광고를 제한하지만, 특정 글 수·글자 수를 채우면 승인된다고 보장하지 않는다. 이번 수정이 승인·순위 상승을 보장한다는 표현도 금지한다. [Google 게시자 정책](https://support.google.com/adsense/answer/10502938?hl=ko)

## 13. Claude의 실행 순서와 산출물

### 묶음 A: 사실 표시·발행 보호·공개 목록

감수 필드/표시 조건, 실패 시 발행 중단, 기존 원고 보호, RSS/태그 공개 필터, 홈의 잘못된 운영 약속을 수정한다. 테스트용 글·임시 저장소로 성공/실패 경로를 검증한다. 실제 감수 이력은 자동 생성하지 말고 운영자 확인 항목으로 남긴다. 기존 사용자 변경은 보존한다.

### 묶음 B: 소수 대표 원고를 끝까지 완성

체지방·항히스타민제·혈압약 시작 후 점검을 먼저 교정하고, 출처 링크가 없는 3편의 근거를 검토한다. 모든 글을 같은 틀로 한꺼번에 덮어쓰지 않는다. 첫 묶음에서 **원문 문제 → 수정문 → 주장 근거 → 실제 감수 → 렌더링 확인**이 연결되는지 보여준다.

### 묶음 C: 전체 84편으로 확대하고 중복 후보 검토

`inventory.json`의 84 URL 각각에 처리 상태·문제·수정 범위·근거·감수 상태·대표 URL 여부를 기록한다. 이 목록의 기계 플래그를 최종 품질 등급으로 사용하지 않는다. 약물·검사 기준·시한성 비용 정보부터 순차 검토한다. 중복 통합은 검색어/페이지 자료와 의료적 구분을 확인한 뒤 결정한다.

### 제출해야 할 결과

- 수정 파일 목록과 핵심 diff. 삭제/URL 변경/redirect는 별도 표로 명시.
- 원고별 교정 전후 예시와 핵심 주장에 대한 근거 대조표.
- 감수 확인 완료 / 운영자 확인 필요 / 수정 후 재감수 필요의 구분.
- 자동 검사 결과와 의도적으로 실패시킨 테스트 결과. 기존 '분량 PASS'와 혼동하지 않기.
- `npm run build` 및 프로젝트에서 실제 사용하는 검사 실행 결과. preview HTML의 title·H1·description·canonical·robots·JSON-LD·출처·감수 표시 확인.
- 모바일 대표 화면에서 표 넘침·읽기 순서·과도한 반복·본문과 광고 구분 확인.
- 배포가 승인된 경우에만 라이브 URL을 재점검하고, 로컬 완료와 배포 완료를 구분해 보고.
- GSC/AdSense 자료가 없는 항목은 '미확인'으로 남기고, 실제 측정일/수정일을 남겨 이후 비교 가능하게 만들기.

첫 28일은 건강 84 URL의 안정된 기준선을 쌓고 이전 기간과 비교하되, 색인 지연·자료 규모·실제 변경일을 함께 해석한다. 28일 또는 90일이 자동 회복 기한이라는 뜻은 아니다. 매주 제목과 공개 범위를 뒤집어 변경 효과를 추적할 수 없게 만들지 않는다.

## 14. 이번 피드백의 최종 요구

**'84편 보강 완료', '표 추가 완료', 'SEO 스키마 완료'를 성공 지표로 쓰지 말 것.**

완료 기준은 독자가 제목에서 약속받은 답을 찾고, 핵심 판단의 근거를 따라갈 수 있으며, 실제 검토된 내용과 표시가 일치하고, 실패한 초안이 배포되지 않는 것이다. 그다음 검색·광고 지표로 성과를 확인한다.
