# Healthpick 글 목차와 읽기 흐름 개선

## 확인한 문제와 범위

앞선 신장기능 글 배포 이후 남긴 모바일 목차 검증 항목을 다시 확인했다. 변경 전 운영 사이트와 로컬의 390x844 화면에서 목차 클릭이 소제목 위쪽 약 128px에 도달하는 것을 확인했다. 앞선 관찰 실패만으로 사이트의 모바일 목차에 결함이 있다고 확정하지 않는다. 일부 키보드 검사에서 중간 스크롤 위치가 관찰된 원인도 특정하지 않았다.

반면 펼쳐진 목차가 첫 화면을 많이 차지하는 점은 재현됐다. eGFR 글에서 목차 높이는 약 221px, 첫 본문 시작은 약 742px였다. 이번 변경은 원고를 수정하거나 색인 설정을 바꾸는 것이 아니라, 목차를 필요할 때 열고 본문을 더 일찍 읽도록 하는 개선이다.

## 구현

- `src/components/TableOfContents.astro`는 기본 접힘 상태의 HTML `details`와 `summary`를 사용한다. 모바일과 데스크톱에 같은 기본 상태를 적용한다.
- 접힌 상태에서도 '목차'와 항목 수를 표시한다. 기존 H2·H3 순서, 각 제목의 앵커와 H3 들여쓰기는 유지한다. 제목이 2개 이하인 글에는 이전과 같이 목차를 만들지 않는다.
- 목차를 이름이 있는 navigation 영역으로 제공한다. 펼치기와 각 링크의 클릭 영역은 최소 44px 높이이며, 키보드 포커스에는 2px 외곽선을 표시한다.
- 펼치기·접기 또는 앵커 이동을 위한 JavaScript는 추가하지 않는다. 링크를 선택한 뒤 목차를 자동으로 접어 본문 위치가 바뀌는 처리도 하지 않는다.
- `src/styles/global.css`의 전역 스크롤 방식을 `smooth`에서 `auto`로 바꿔 앵커 이동을 즉시 수행한다. 기존 소제목의 `scroll-margin-top: 8rem`은 유지한다. 이 변경은 글 목차뿐 아니라 사이트의 다른 앵커 이동에도 적용된다.

[MDN details 문서](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details)의 기본 접힘·키보드 조작 방식과 [scroll-behavior 문서](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-behavior)의 즉시 이동 동작을 참고했다. 이 구현만으로 모든 기기나 보조 기술에 대한 접근성 준수를 검증한 것은 아니다.

## 실제 화면 검증

로컬 eGFR 글의 390x844 화면에서 접힌 목차는 46px, 첫 본문 시작은 약 566px였다. 변경 전보다 본문 시작이 약 175px 위로 올라왔다. 펼친 링크 높이는 44px 또는 66px였다.

Space로 접고 펼치기, Enter로 펼치기, Tab으로 첫 링크에 포커스, 클릭과 Enter로 소제목 이동을 검사했다. 최종 즉시 이동 방식에서 모바일 클릭·키보드 도착 위치는 약 128px였고, 1280x720 데스크톱의 키보드 이동도 약 128px에 도달했다. 각 검사에서 실제 viewport 크기를 별도로 읽었으며, 서로 다른 탭에 크기 설정이 같은 시점에 적용됐다고 가정하지 않았다.

## 검증과 배포

최종 테스트 19개와 746페이지 빌드가 통과했다. 변경 전 빌드의 발행 글 362개(건강 92개, 기존 다른 카테고리 270개)를 기준 자료로 저장하고 새 빌드와 비교했다. 전체 362개에서 원고 파일·본문·구조화 데이터·외부 링크·canonical·robots·OG 메타데이터가 동일했고 OG 이미지 파일도 보존됐다. 목차 362개의 기본 접힘, 항목 수, H2·H3 순서·대상·문구·들여쓰기와 키보드 포커스 클래스도 검사했다. 생성 CSS의 즉시 스크롤 설정을 확인했다.

사이트맵은 102개 중 건강 URL 92개, 건강 글 수정일 누락 0개이며 RSS 50개는 모두 건강 글로 유지된다. 원고의 발행일·수정일·감수 기록을 변경하지 않았다.

빌드 로그·전체 출력 검사·운영 배포와 실제 운영 화면 결과는 소유자의 `output/healthpick-2026-10-23-reading-ui` 폴더에 남긴다. 기계적 검사와 화면 표본 검증의 범위를 구분하며, 원고의 의학적 타당성이나 검색 색인 회복을 판정하는 검사는 아니다.

## Claude 인계

1. 원고와 공통 레이아웃 변경을 구분한다. 이번 작업으로 글별 발행일·수정일·의료 감수 기록을 일괄 변경하지 않는다.
2. 목차 링크를 선택한 뒤 자동으로 접거나 사용자 스크롤을 다시 조정하는 코드를 추가하지 않는다. 기본 링크 동작과 헤더 여백을 먼저 검증한다.
3. 이전의 검증 실패는 같은 화면 크기와 입력 방식에서 재현한 뒤 판단한다. URL hash 변경과 실제 도착 위치를 각각 확인한다.
4. 전체 정적 출력 검사와 표본 UI 검증을 혼동하지 않는다. 이 변경을 유입 증가나 AdSense 승인 개선의 증거로 설명하지 않는다.

새 글 발행, GSC 재요청, 사이트맵 재제출, 자동 대량 발행은 이번 작업 범위에 넣지 않는다. 기존 미추적 `scripts/quality-audit.mjs`도 수정하거나 커밋하지 않는다.
