- 읽기 시간에서 임의로 만든 `wordCount`와 최소 1000이라는 구조화 데이터 값을 제거했다.

## 기계적 점검 도구

```powershell
npm run audit:content
npm run audit:content -- --output <결과.json>
```

`scripts/lib/content-inventory.mjs`는 YAML과 Markdown AST를 읽는다. 일반 링크뿐 아니라 GFM 원문 URL과 참조 링크도 세고 코드 예시의 URL은 제외한다. 글 91편 모두 외부 참조가 있지만, 기관 홈페이지를 참조에 포함한 글은 여전히 54편이다. 링크가 있다는 사실만으로 그 주장의 근거가 충분하다고 판정하지 않는다.

이전 단순 정규식 점검과 달리 PTSD 글에는 기존 원문 URL 참조가 있었음을 확인했다. '출처 전무'로 분류하면 안 된다. 출처가 없던 근지구력·로우푸드 2편에는 직접 출처를 추가했다. 현재 91편의 내용에 대응하는 의료 감수 기록은 등록되어 있지 않다. 이것은 실제 감수가 과거에 한 번도 없었다는 증거가 아니다.

## 자동화: 생성과 발행 분리

기존 두 PowerShell 자동화에는 생성 실패 뒤에도 변경 파일을 커밋·push할 수 있는 경로와 다주제 수량 할당이 있었다. 해당 동작을 제거했다. Task Scheduler의 `HealthpickDailyContent`는 비활성 상태를 유지하며 재활성화하지 않았다.

- `daily-content.ps1`와 `daily-content-3per-day.ps1`는 명시적 `-GenerateDraft -Topic` 없이는 오류로 종료한다. 기존 무인 실행이 곧바로 발행을 재개하지 않는다.
- `generate-content.mjs`의 레거시 생성·`--clean`은 파일을 변경하지 않고 오류로 종료한다. `npm run generate`도 이 경로다.
- 새로운 명시적 초안 명령: `npm run draft -- -Topic "작성할 건강 주제"`
- PowerShell 7, Node 24 및 인증된 Claude CLI가 필요하다. Claude 호출에는 회당 최대 2달러의 예산 제한이 있으며 실제 사용 시 과금될 수 있다.
- Claude에는 웹 검색·열람 도구만 제공한다. 안전 모드와 엄격한 MCP 설정을 사용하며 파일 편집·셸·git 도구는 주지 않는다.
- 결과 JSON과 검증된 Markdown은 git에서 제외한 `.drafts/`에만 새 파일로 저장한다. `src/content`에는 쓰지 않고 커밋·push도 하지 않는다.
- CLI 실패, 비정상 JSON, 공급자 오류, `draft:false`, 허위 의료 감수, 홈페이지 출처 또는 본문 인용 누락 등은 실패 처리한다.
- 검증 통과는 형식 요건 충족일 뿐, 사실 확인·의료 감수·발행 승인이 아니다. 사람이 출처의 원문과 글의 주장을 비교한 뒤 별도 발행해야 한다.
- 이번 검증은 모의 CLI로 실행했다. 유료 Claude 생성이나 스케줄러를 실제 가동하지 않았다. 새 글은 직접 조사·편집했다.

- 공개 건강 글은 90편에서 91편으로 증가한다. 비건강 카테고리 270편은 이번에 삭제하지 않았다. 기존 URL 접근과 `noindex`는 유지되며 보안상 비공개인 것은 아니다.
- `npm test` 19개 통과. 최종 정적 빌드는 741페이지로 성공했다. HTML 출력 검사 7개 묶음도 통과했다. 검색 데이터는 91편, 건강 태그 페이지는 346개다.
- XML 검사에서 사이트맵 101개 중 건강 URL 91개, 건강 글의 `lastmod` 누락 0개를 확인했다. RSS 50개는 모두 건강 글이며 새 글도 포함된다. 재현용 로그와 검증 스크립트는 소유자의 `output/healthpick-2026-10-23` 작업 폴더에 둔다.
- `npm audit`는 31개 패키지 경고(critical 2개 포함)를 보고했다. Astro·Vercel 어댑터 등 기존 빌드 체인의 업그레이드 검토가 필요하다. 정적 출력이라는 사실만으로 위험이 없다고 결론 내리지 않으며, 이번 편집과 섞어 강제 메이저 업그레이드는 하지 않았다.

### Claude에게 넘길 우선순위

1. 수동 요청을 같은 URL에 반복하지 말고 Search Console에서 대표 건강 글의 발견·마지막 크롤링·색인 상태 변화를 비교한다. 사이트맵 성공이나 요청 접수는 검색 노출 회복의 증거가 아니다.
2. 오래된 제외 URL 전체를 현재 발행 글의 실패로 계산하지 않는다. 현재 공개 건강 URL 집합과 과거 삭제·리디렉션·의도적 `noindex` URL을 분리한다.
3. 홈페이지 출처 54편을 위험도 순으로 실제 주장별 직접 문서로 교체한다. 제목만 바꾸거나 일괄 수정일 갱신을 하지 않는다.
4. 혈당·혈압·지방간 등 숫자만 다른 유사 글의 검색 의도를 비교한 뒤 통합 여부를 결정한다. 통합할 때만 개별 리디렉션을 검토한다.
5. 부분 편집된 글의 남은 본문·FAQ를 재확인하고, 실제 의료 감수 기록을 확보한 내용에만 검토자·날짜·해시를 등록한다.
6. Astro 및 관련 의존성 보안 업그레이드는 별도 변경에서 정적 배포·슬러그·원본·RSS·검색·구조화 데이터 회귀 검증과 함께 진행한다.

기존 미추적 `scripts/quality-audit.mjs`는 소유자의 별도 작업으로 취급해 수정·커밋하지 않는다.
