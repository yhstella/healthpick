# Healthpick 빌드 보안 업데이트와 Claude 인계

## 이번 작업의 범위

원고 교정을 진행하던 중 발견한 오래된 빌드 의존성을 업데이트했다. 이것은 유입 부진의 원인을 보안 취약점으로 확정하거나, 프레임워크 업데이트만으로 색인이 늘어난다고 주장하는 작업이 아니다. 신규 글 추가나 의료 감수도 아니다. 원고 소스와 발행일·수정일은 바꾸지 않는다.

업데이트 전 기준은 `50c10c88414195598d3a442f9d8a1dc5c4072a65`다. 공개 원고 359편, 그중 건강 89편의 소스·본문 HTML·구조화 데이터·raw·OG와 전체 정적 파일 목록을 별도로 저장했다. 계정 화면과 상세 검증 증거는 공개 저장소가 아닌 소유자의 `output/healthpick-2026-10-23-security` 폴더에 둔다.

## 의존성 처리

| 대상 | 처리 |
| --- | --- |
| Astro | 설치 버전 4.16.19에서 7.4.2로 업데이트 |
| Vercel 어댑터 | 7.8.2에서 11.0.16으로 업데이트. 폐기된 `/static` import 대신 기본 export 사용 |
| MDX | 3.1.9에서 8.1.1로 업데이트. 현재 MDX 원고는 없지만 지원 형식은 유지 |
| 사이트맵 | 3.1.6에서 3.7.4로 업데이트. 구버전의 빌드 훅이 새 Astro에서 실패하는 문제 확인 |
| RSS | 4.0.18에서 보안 수정된 4.0.19로 업데이트 |
| Markdown | `@astrojs/markdown-remark` 7.3.4를 명시해 기존 unified 파이프라인 유지 |
| Tailwind | 3.4.19 유지. 구 Astro 전용 통합을 제거하고 동일한 Tailwind + Autoprefixer PostCSS 파이프라인으로 연결 |
| 기타 패치 | 강제 옵션 없는 `npm audit fix`로 호환 범위 안의 YAML·폰트 압축 처리 등 업데이트 |

2026-10-23 이 차수 시작 시 `npm audit` 결과는 패키지 경고 항목 30개였다. `npm ci`로 재설치한 뒤 개발 의존성까지 포함하고 새 감사 캐시로 확인한 최종 보고서는 11개다. critical은 2에서 0, high는 18에서 8, moderate는 9에서 3, low는 1에서 0이다. 이전 차수의 31개 보고서와 이번 기준 파일을 혼용하지 않는다. 상위 패키지에 전파된 항목이 포함되므로 이를 서로 다른 취약점 개수라고 부르지 않는다. 경고를 숨기거나 무시 목록을 추가하지 않았다.

중간 감사에서는 같은 최종 lockfile로 15개가 보고됐다. 최종 11개 보고서에서 아래 sprintf 경로가 빠졌지만 설치 버전은 그대로이므로, 이 네 패키지 경로까지 수정됐다고 계산하지 않는다. 보수적으로 별도 미해결 추적 대상으로 남긴다. 감사 서비스의 응답 개수만으로 취약점 해결 여부를 판정하지 않는다.

남은 항목은 주로 다음 네 경로다. 모두 해결됐다고 보고하면 안 된다.

1. Tailwind 3의 glob/watch 의존성에서 `braces`까지 이어지는 경로. 임의로 중첩 패턴을 입력받는 빌드·개발 환경에 주의한다.
2. Tailwind 3·typography의 `postcss-selector-parser` 경로. 외부 CSS를 검증 없이 빌드 입력으로 받지 않는다.
3. 최신 Vercel 어댑터의 `@vercel/routing-utils`가 고정한 `path-to-regexp` 6.1.0. 이 프로젝트는 서버 함수를 배포하지 않고, 어댑터는 빌드 시 정적 라우팅 설정을 만든다. 따라서 사이트 방문 요청마다 이 Node 라이브러리를 실행하는 구조와는 다르다. 이 차이가 모든 위험이 없다는 증명은 아니다.
4. `gray-matter` → `js-yaml` → `argparse` → `sprintf-js` 경로. YAML 자체의 해당 high 경고들은 패치로 제거됐지만 `sprintf-js` 1.0.3은 그대로다. 공개 보안 공지의 영향 범위에 포함되므로 최종 npm 보고에서 빠진 것을 해결로 간주하지 않는다. 파서는 저장소 원고를 빌드 때 처리한다.

`npm audit fix --force`가 제안하는 Astro 어댑터·gray-matter의 과거 버전으로의 변경을 적용하지 않는다. 지원 여부를 확인하지 않은 override도 넣지 않는다. Tailwind 4로의 전환은 별도 작업으로 남긴다. 공식 문서상 최소 브라우저 범위와 여러 유틸리티·색상·CSS 동작이 달라지므로 경고 수만 줄이려고 함께 변경하지 않았다.

## 동작 보존과 실제 수정

- 콘텐츠 설정은 `src/content/config.ts`에서 `src/content.config.ts`로 이동하고 glob 로더를 사용한다. `entry.slug` 대신 `entry.id`, `entry.render()` 대신 `render(entry)`를 사용한다. URL 정규화는 전체 산출물로 대조한다.
- 본문이 없는 로더 결과는 빈 글로 발행하지 않고 명시적으로 실패시킨다. 읽는 시간·감수 해시·raw 원문이 같은 본문을 사용한다.
- `gfm: false`와 `remark-gfm`의 `singleTilde: false` 조합을 유지한다. `60~100`, `6~12개월`이 취소선으로 변하지 않아야 한다. 표·정상적인 이중 물결 취소선·목차 앵커도 검사한다.
- `compressHTML: true`를 명시해 새 기본값으로 인한 인라인 텍스트 간격 변화를 피한다. 기존 Tailwind 설정·스타일시트·폰트·이미지 선택은 바꾸지 않는다.
- Markdown 로더가 본문 경계 공백을 정리하므로 raw 출력에는 빈 줄을 명시한다. 원문 내용 누락과 단순한 앞뒤 공백 변화는 구분해서 검증한다.
- 새 Vercel 어댑터의 `staticHeaders` 구현은 현재 CSP만 출력한다. 옵션만 켜고 raw의 canonical·캐시가 배포된다고 간주하면 안 된다. `raw-static-headers.mjs`가 수집된 raw 응답의 Content-Type·Cache-Control·X-Robots-Tag·Link만 정적 출력 설정에 추가한다. Set-Cookie 등 다른 헤더를 복제하지 않는다.
- raw 규칙은 인코딩된 경로에 정확히 일치하도록 고정하고 filesystem 처리 전에 넣는다. 서버 함수나 동적 이미지 서비스를 추가하지 않는다. 루트 `vercel.json`의 기존 리다이렉트·보안 헤더는 변경하지 않는다.

## Claude에게 중요한 운영 피드백

과거 설정 주석에 있던 "일괄 lastmod가 scaled content abuse를 일으켜 노출 0의 직접 원인이 됐다", "사이트맵의 noindex 때문에 품질 평가가 내려갔다"는 단정은 확인된 증거가 아니다. 이 파일에서 해당 인과 단정을 제거했다. 사실에 맞는 변경일을 기록하고 noindex URL을 검색용 사이트맵에서 제외하는 운영 원칙은 유지한다. 올바른 조치라는 사실과 특정 장애의 원인이 입증됐다는 주장은 다르다.

마찬가지로 `npm audit`의 critical 표시와 운영 사이트에서 실제로 악용 가능한 경로는 구분해야 한다. Astro의 AVIF 취약점은 공격자가 신뢰할 수 없는 AVIF 처리를 유발할 수 있는 조건을 다룬다. 현재의 정적 출력·로컬 폰트 기반 OG·동적 이미지 서비스 비활성화가 노출을 줄이지만, 빌드 도구를 계속 구버전으로 둬도 된다는 뜻은 아니다. 개발 서버는 외부에 공개하지 않고, 신뢰하지 않는 저장소·이미지·패턴을 권한이 있는 빌드에 넣지 않는다.

공개 건강 글 89편을 실제 의료 감수 완료 글로 바꾸지 않는다. 기존의 감수 기록 없음 안내와 해시 검증을 유지한다. 원고를 고치지 않은 이 차수에서 모든 글의 `updatedDate`를 오늘로 바꾸거나 GSC 색인 요청을 다시 반복하지 않는다. 최근 접수한 일곱 URL의 요청 수락과 실제 색인 완료는 별도 상태다. GSC의 과거 집계 740개를 현재 공개 건강 글 수로 해석하지 않는다.

## 검증 기록

전체 테스트 51개와 747페이지 정적 빌드가 통과했다. 전체 359편의 소스·구조화 데이터·OG가 그대로이며 URL 및 정적 파일의 누락·추가는 없다. 건강 글 89편의 기존 감수 기록 없음 안내도 유지된다. 사이트맵은 총 99개 중 건강 89개, 건강 lastmod 누락은 0개, RSS 50개는 모두 건강 글이다.

본문 HTML 349편은 완전히 동일하다. 나머지 10편 중 9편은 표 안의 여는 따옴표 방향 교정뿐이고, 비공개 카테고리의 SQL 글 한 편은 코드 끝 빈 줄 5개가 없어졌다. 실제 코드·의학적 문구는 변경되지 않았다. raw 355편은 바이트까지 동일하며 나머지 4편도 본문 경계 공백만 다르다. 전체 raw에 대해 원본 경계 공백을 되돌렸을 때 업데이트 전 SHA-256과 일치함을 확인했다. 이런 차이를 숨기고 "모든 HTML이 동일하다"고 보고하지 않는다.

raw 헤더 규칙 359개가 정확한 인코딩 경로와 canonical을 갖고 filesystem 앞에 배치된다. 생성된 서버 함수·동적 이미지 서비스 설정은 없다. 어댑터가 정규식 표기를 정규화한 두 곳 외 기존 정적 라우팅은 유지된다. 원고 화면은 1280×720과 390×844에서 제목 크기·본문 폭·목차 기본 상태가 업데이트 전과 같다. 모바일 메뉴 펼침도 확인했다. 운영 배포 결과는 별도 산출물에 기록한다.
