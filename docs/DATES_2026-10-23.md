# Healthpick 날짜 정밀도와 사이트맵 이미지 수정

## Claude에게 전달할 핵심

게시일에 날짜만 적혀 있다는 사실과, 실제로 UTC 자정에 게시했다는 사실은 다르다. `2026-10-23`을 `2026-10-23T00:00:00.000Z`로 내보내면 한국 시간 오전 9시라는 확인되지 않은 시각이 생긴다. 같은 날 오전 6시대에 이미 공개된 새 헬리코박터 글에서는 미래 시각이 되는 문제가 있었다. 날짜를 일괄 오늘로 바꾸거나 빌드 시각을 게시 시각으로 대신 기록하지 않았다.

수정 전 기준은 `e1c3eaf117ce69566ba275455db264d8383ae9fd`이다. 직전 차수의 원고 네 편 교정과 새 글 한 편은 [소화기 편집 피드백](./DIGESTIVE_2026-10-23.md)에 별도로 정리되어 있다. 이번 작업은 그 원고를 다시 고치는 작업이 아니라 공통 출력 계층의 오류 수정이다.

## 확인한 원인

1. Astro의 YAML 파서는 따옴표 없는 날짜를 JavaScript `Date`로 바꾼다. 이후 `z.coerce.date()`를 거치면 원본이 날짜뿐이었는지, 실제 자정 시각이었는지 구별할 수 없다. 기존 사이트맵용 gray-matter 파서도 같은 정보를 잃었다.
2. 구조화 데이터와 Open Graph, HTML `time`에서 무조건 `toISOString()`을 호출했다. 사이트맵 라이브러리도 날짜 문자열을 다시 자정의 UTC 시각으로 확장했다. 한 곳의 문자열만 수정해서는 해결되지 않는다.
3. 화면 날짜의 `Intl.DateTimeFormat`에 시간대가 없었다. 예를 들어 `2026-05-19T23:59:00.000Z`는 한국에서 5월 20일이지만 UTC 빌드 서버에서는 5월 19일로 보였다. raw Markdown은 UTC 날짜만 잘라 화면과 달랐다.
4. 별도 대조 중, 사이트맵의 한글 OG 이미지 주소가 이중 인코딩되어 `%25EA...` 형태로 나가는 기존 오류를 발견했다. 운영 중인 갑상선 결절 글의 사이트맵 이미지 주소에서 HTTP 404를 직접 확인했다. 이미지 파일이나 HTML 글 URL 문제가 아니라 사이트맵 참조의 문제였다.

전체 원고 소스 364개에는 날짜만 있는 게시일 221개, 실제 시각이 있는 게시일 143개가 있다. 수정일은 날짜만 있는 값 29개와 실제 시각 4개다. 보관 초안을 포함한 수치이므로 공개 글 360편의 통계와 혼동하지 않는다. 명시적인 `...T00:00:00.000Z`와 `...T09:00:00+09:00`은 실제 시각으로 보존한다. 자정이라는 이유로 날짜만 있는 값이라고 추측하지 않는다.

## 구현과 작성 규칙

- 원고 파일의 날짜나 본문을 대량 재작성하지 않았다. Astro의 기존 glob 로더가 ID·렌더링·이미지·변경 감지를 계속 담당하며, 스키마 검증 전에 원문 YAML에서 날짜 필드 두 개만 문자열로 복구한다. YAML은 정규식으로 읽지 않고 core 스키마로 파싱한다.
- `pubDate`와 `updatedDate`의 `Date` 객체는 기존 정렬용으로 유지한다. 기계 출력에는 새 `pubDateISO`·`updatedDateISO`를 사용한다. 날짜만 있으면 `YYYY-MM-DD`, 시각이 있으면 동일한 순간의 UTC ISO 문자열이다. 정렬용 객체를 실제 게시 시각으로 다시 출력하지 않는다.
- 새 원고에도 날짜만 아는 경우 `pubDate: 2026-10-23`처럼 쓴다. 실제 시각을 기록한다면 초와 명시적인 시간대를 포함한다. 예: `2026-10-23T06:30:00+09:00`. 시간대 없는 시각, 존재하지 않는 날짜, 이미 정밀도를 잃은 Date 객체는 새 검증에서 거부한다.
- JSON-LD·Open Graph·HTML `datetime`은 원본 정밀도를 보존한다. 화면·카드·홈·raw의 달력 날짜는 날짜 전용 값을 그대로 쓰고, 실제 순간에 대해서만 `Asia/Seoul`의 날짜를 표시한다.
- 정밀도 복구의 대상은 게시일·수정일 두 필드다. 별도 의료 감수 기록의 검증·해시 정책은 바꾸지 않았다. 현재 없는 실제 감수 기록을 입력할 때는 `reviewedAt`의 정밀도와 표시 시간대도 별도로 점검해야 하며, 게시일이나 편집일로 감수일을 채우지 않는다.
- 사이트맵은 원고별 `lastmod`를 보존한다. 현재 라이브러리의 강제 UTC 변환 후 XML을 구조적으로 읽어 원래 정밀도로 복구한다. 검증되지 않은 URL의 `lastmod`는 조용히 통과시키지 않는다. 사이트맵 인덱스에 페이지 수정일을 파일 수정 시각처럼 복사하던 선택적 `lastmod`는 생략한다.
- RSS 2.0의 `pubDate`는 시각이 필요하므로 실제 시각을 아는 글에만 기록한다. 날짜만 있는 글은 선택적 `pubDate`를 생략하고 Dublin Core `dc:date`에 날짜를 제공한다. GUID·링크·글 수는 유지한다. 이 확장을 읽지 않는 구독기는 게시일 표시를 생략할 수 있으며, 모든 구독기가 날짜를 해석한다고 보장하지 않는다.
- 첫 운영 대조에서 같은 게시일을 가진 RSS 항목의 순서가 로컬과 달랐다. 비동기 glob 로더의 완료 순서가 정렬 동률과 50개 경계의 구성원을 결정하고 있었다. RSS에 한해 날짜 동률을 글 ID의 고정 순서로 정했다. 기존 날짜·GUID 형식·링크 형식·50개 제한을 유지하되, 과거의 불안정했던 동률 순서와 경계 항목은 바뀔 수 있다.
- 사이트맵 이미지 주소는 경로 슬러그를 한 번 해제한 뒤 한 번 인코딩한다. 실제 PNG와 OG 디자인, 정규 HTML URL은 변경하지 않는다.
- YAML 2.9.1과 fast-xml-parser 5.8.0을 직접 의존성으로 선언했다. 이미 설치되어 있던 버전이며 잠금 파일에서 다른 패키지의 버전은 변경하지 않았다. 이 작업은 남아 있는 의존성 취약점을 해결한 작업이 아니다.

## 근거와 해석 범위

- [Google 게시일 안내](https://developers.google.com/search/docs/appearance/publication-dates): 날짜는 필요하지만 시각은 선택 사항이며, 표시와 구조화 값의 일관성과 미래 날짜 방지를 설명한다.
- [Schema.org datePublished](https://schema.org/datePublished): `Date`와 `DateTime`을 모두 허용한다.
- [Open Graph](https://ogp.me/): DateTime의 시간 부분은 선택 사항이다. 따라서 날짜 전용 값을 위해 가짜 시각을 추가하거나 메타 태그를 모두 버릴 필요가 없다.
- [사이트맵 프로토콜](https://www.sitemaps.org/protocol.html): `lastmod`에 `YYYY-MM-DD`를 허용하고, 페이지 변경일과 사이트맵 파일 변경일을 구분한다.
- [RSS 2.0](https://www.rssboard.org/rss-2-0-11): `pubDate`는 선택 항목이며 RFC822 형식의 시각이다. [Dublin Core date](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/elements11/date/)는 날짜의 정밀도를 유지할 수 있다.

이 규격 대조는 날짜 처리의 근거다. 날짜와 이미지 참조 오류가 '색인 1개'의 주원인이라는 인과관계, 수정 뒤 색인이나 유입이 회복된다는 보장은 확인되지 않았다. 날짜를 최근으로 바꾸는 것 자체가 콘텐츠 품질 개선은 아니다.

## 검증 결과

최종 테스트 74개와 751페이지 정적 빌드가 통과했다. 추가 검사는 따옴표 유무, 날짜와 명시적인 자정 시각의 구별, 존재하지 않는 날짜와 시간대 없는 시각의 거부, UTC·한국·로스앤젤레스 빌드 시간대의 동일 출력, 로더의 기존 컨텍스트 보존, RSS와 사이트맵 혼합 정밀도, 잘못된 XML과 예기치 않은 경로의 거부, 한글 이미지 단일 인코딩을 다룬다. 운영 대조에서 발견한 RSS 동률 정렬에는 반대 로더 순서에서도 같은 50개 항목이 선택되는 추가 회귀 검사를 배치했다. 본문 대조와 XML·라우팅 검증도 최종 빌드에서 다시 통과했다.

전체 공개 360편의 소스·렌더링 본문·OG 이미지 바이트와 날짜 외 구조화 데이터가 수정 전과 일치했다. 게시일은 날짜 전용 219편·실제 시각 141편이다. 수정일이 없을 때 게시일을 쓰는 기존 정책을 포함해 `dateModified`의 날짜 전용 값은 233편이다. raw Markdown 44편의 날짜 헤더가 한국 날짜로 바뀌었고, 그 헤더만 이전 UTC 날짜로 되돌리면 360편 모두 이전 raw 해시와 일치한다.

정적 경로 1481개·raw 헤더 규칙 360개·Vercel 라우팅 설정이 그대로다. 이전 비공개 카테고리 270편의 noindex와 목차 앵커 5112개도 유지된다. 사이트맵은 100개 URL 중 건강 글 90개이며 각 `lastmod`가 원고 정밀도와 일치한다. 이미지 90개도 실제 출력 파일 경로와 대응한다. RSS 50개 중 날짜 전용 49개는 `dc:date`, 실제 시각 1개는 `pubDate`로 제공한다.

검증 스크립트·빌드 로그와 운영 확인 결과는 소유자 로컬 `C:/Users/R/Dropbox/output/healthpick-2026-10-23-dates/`에 보관한다. 운영 확인에서는 건강 HTML 90편의 본문·구조화 데이터·표시 날짜, 혼합 날짜 유형의 raw 표본, 사이트맵·RSS 및 이미지 응답을 대조한다. 계정 화면과 개인 자료는 저장소에 넣지 않는다.

## GSC 운영 제한과 남은 과제

직전 차수에서 새 제균 확인 글의 실시간 URL 검사는 통과했다. 다만 색인 요청은 일일 할당량 초과로 거절됐으며 수락되지 않았다. 앞서 수락된 서로 다른 일곱 URL과 구별해서 기록한다. 한국 시간 2026-10-24 전에는 재시도하지 않는다. 정확한 할당량·초기화 시각은 확인하지 못했으므로 임의의 수치를 약속하지 않는다. 우회 API나 다른 계정, 반복 제출을 사용하지 않는다.

사이트 전체 보고서의 마지막 확인 집계는 2026-10-16 기준 미색인 740개·색인 1개였다. 이 오래된 집계와 현재 공개 건강 글 90개를 동일한 모집단으로 보지 않는다. 실제 색인·노출·유입 회복은 여전히 별도 확인이 필요하다. 이번 기술 수정 때문에 본문 수정일이나 의료 감수일을 오늘로 갱신하지 않았다. 공개 건강 글의 실제 감수 기록 90편 미등록, 기관 홈페이지 참조의 기계적 검토 대상 38편도 그대로 남아 있다.

후속 콘텐츠 편집은 이전 피드백의 호흡기 원고 검토를 이어간다. 기침 기간의 분류를 진료 전 최소 대기 시간으로 만들지 않는지, 직접 근거와 독자 행동 순서를 확인한다. 자동 대량 발행과 보관 원고 재공개는 재개하지 않는다.
